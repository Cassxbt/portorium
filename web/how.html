01 · Retriever

Find the rulings an importer could have cited that day.

The product description is embedded with Nemotron Embed and compared against 56,371 CBP ruling subjects. Only rulings issued before the date of the question count. The 20 nearest are re-ordered by Nemotron Rerank and the top six go forward.

Why it matters

A precedent from after the question date would be hindsight. The evaluation applies the same cut-off, so no system sees a ruling issued after the items it is scored on.

What it cannot do

Choose a code. It only proposes candidates; product facts for each come from the ruling text on CBP's site.

02 · Memory

Remember what a broker signed and what the importer said.

Broker sign-offs and the importer's answers are long-term memories in Meterless H-MEM, with provenance. For a similar product they are recalled and judged alongside the rulings, never trusted blindly.

Why it matters

A broker's correction should hold for the next shipment of the same article, and a question answered once should not be asked again.

What it cannot do

Override a dead code. A remembered decision whose code is no longer in the schedule is dropped before judging; one that contradicts a living precedent sends the case to review.

03 · Auditor

Ask Zetaris whether each precedent is still alive.

The schedule (HTS 2026 Rev 21), the rulings and their codes live in a Zetaris virtual layer. Two registered data-quality rules decide liveness: code_in_schedule and parent_survives. For every request, one query returns each precedent's revocation flag and the status of its codes.

Statuses

living the code is in Rev 21 · split its 8-digit parent survives under new codes · removed gone · revoked the ruling itself no longer stands.

Across all rulings

Of 75,870 ruling codes, 53,723 are living, 7,938 split and 14,209 removed.

04 · Adjudicator and Proposer

Two calls at once: is it the same article, and which code?

Nemotron 3 Ultra, routed through Meterless Nightshift, runs twice in parallel. The Adjudicator marks each precedent as the same article, a similar one or a different one, and writes the single question that would separate them. The Proposer picks one code, only from the codes the retrieved rulings cite, with a confidence.

Why a proposal, not a vote

On the dev set, Ultra's pick among retrieved rulings was the strongest single signal. Asked for a code from memory, the same model named a code no longer in the schedule for over a third of products.

Receipts

Each call returns a Nightshift receipt naming the model that ran it. The verdict keeps both.

06 · Critic

A living code can still mean something else now.

In HTS 2026 Rev 21, 3004.90.92.35 reads "Containing tramadol". A 2023 ruling had used it for olanzapine, which now has its own line. The code survived the revision; its meaning moved. So before a code is given, Zetaris returns its full Rev 21 text, every level from the heading down, with the alternatives at each level, and Nemotron Ultra checks the product against it.

What it catches

Renumbered statistical lines; a single-loudspeaker line given to a two-speaker product; training balls given a line for baseball equipment "except balls". When a missing fact decides it, the Critic writes the question. It also misses some, and sometimes rejects a right code: the evaluation counts both.

How it is built

One Zetaris query walks the schedule's indentation: the last line at each level above the code, and every sibling at each level. No text is hard-coded.

07 · Importer · Broker

One question, then the whole loop again.

On review, the importer gets the single question the Adjudicator wrote. The answer is stored in memory and the request runs again from the Retriever, with the answer in front of the Adjudicator. A licensed broker can sign off any code; the sign-off becomes memory for the next shipment.

Ledger

Every live verdict is written to a Zetaris audit table. A rule, classified_code_living, re-screens past verdicts when the schedule changes.

Wipe

Memory can be wiped per importer. H-MEM's ledger keeps a record of each deletion.
